# 知识库治理与权威来源

> 目的：让每个业务问题只有一套可追溯的答案，避免 RAG 因资料冲突而生成矛盾回复。
>
> 生效日期：2026-09-20

## 一、权威来源原则

1. **详细规则优先于概览和 FAQ**：涉及具体价格、时间、资格、退款或责任时，以对应的详细规则文件为唯一事实来源。
2. **FAQ 只作简短解释**：`常见问题FAQ.md` 可以被检索和引用，但其中的数值与规则必须和详细规则同步；发生不一致时，以详细规则为准。
3. **历史稿不进入索引**：已废弃资料放在 `data/archive/`，而不是 `data/documents/`。当前加载器只读取 `data/documents/`。
4. **一次只改一个事实源**：先改权威文件，再同步 FAQ，随后重建索引并运行评测。

## 三、已归档资料

| 文件 | 处理原因 |
|---|---|
| `data/archive/寄养服务须知_已废弃.md` | 其中的价格、节假日倍率、退改和多宠优惠规则与当前详细规则冲突，因此不参与检索。 |

## 四、更新流程

1. 如果修改价格，先修改 `data/pricing_rules.json`，再同步 `data/documents/价目表.md`；其他规则修改本表中对应的权威文件。
2. 检查 `常见问题FAQ.md` 是否需要同步。
3. 运行 `python -m app.main --rebuild` 重建索引。
4. 运行 `python evaluation/retrieval_eval.py`，查看 `docs/检索评测报告.md`。
5. 运行 `python -m unittest discover -s tests`，确认算价规则没有回归。
6. 如果有案例失败，先检查资料、检索和评测标注，再修改代码。
