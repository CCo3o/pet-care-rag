# 宠物寄养智能助手 · 功能清单 v1.3

> 定位：寄养门店部署的 C 端智能客服，替店主回答顾客咨询。
> 形态：网页版对话界面（FastAPI + SSE），开发期 CLI 调试。

## 一、核心功能（8 项）

### F1 知识问答（主链路）
顾客咨询门店政策、价格规则、宠物护理知识，助手基于店内文档回答，**每条回答附引用来源**。
覆盖范围：寄养协议、疫苗要求、退改规则、价目、猫/狗/异宠护理、应急处理建议。
- 实现阶段：步骤 2-5（切分实验 → 评测集 → 混合检索 → 重排序）
- 验收标准：评测集上 recall@5 与回答忠实度达标，且每次优化有前后对比数据

### F2 业务算价
"中型犬寄养 5 天多少钱""春节 10 天呢"——走结构化查询（function calling 查价目表 + 折扣/上浮规则计算），不走 RAG 文本生成，保证数字准确。
- 实现阶段：基础算价及自然语言工具调用已接入 CLI；支持缺参追问、调试输出。仅单宠基础费，全程同类时段；多宠/增值服务/跨档期暂不支持。
- 验收标准：价格类问题 100% 数字正确（例如中型犬 10 天享 9 折：118×10×0.9=1062）

### F2b 档期查询（实时房态）
"现在还有位置吗""十一那周能订吗"——动态状态，RAG 无法回答（知识库是静态文档），走 function calling 实时计算。
- **数据源**：`data/bookings.sqlite3`（共享模拟订单）+ `data/booking_capacity.json`（模拟容量配置）
- **计算方式**：逐日容量计算——区间内每天占用 = 与该天重叠的有效订单数，剩余 = 容量 − 占用
- **应答形态**：逐日占用及余位，全程有位 / 部分日期满 / 全部已满；自动推荐替代日期与候补尚未实现
- **超卖保护**：确认时在同一 SQLite 写事务中重新检查并占位；重复请求编号不会重复占位
- 设计动机（真实经历）：主理人做过家庭寄养，满员时顾客仍反复咨询档期，人工逐条回复成本高
- 架构演进（面试素材）：初版设计为店家人工维护房态文件，后改为由接单记录派生计算，避免派生数据与事实不一致
- 实现阶段：已接入 CLI 工具调用、明确确认后的本地演示预订，以及同会话/订单编号取消；起止日均占位。共享订单独立于聊天记录，无真实支付、身份认证。
- 验收标准：不出现"文档说有位、实际已满"的矛盾；跨月 / 长期订单 / 部分日期满员等边界计算正确

### F3 多轮对话
承接上下文："我家猫 3 岁"→"它寄养要注意什么"→"一天多少钱"，支持指代（它/我家那只）与省略问句。
- 实现阶段：步骤 6（会话记忆 + 查询改写）
- 当前进度：报价追问及跟进已携带当前会话最近8轮历史；`/clear` 清空。不代表完整多轮评测或跨会话持久记忆已完成。
- 验收标准：多轮测试集上改写后问题命中正确文档

### F4 意图路由
四种意图分流：知识问答（走 RAG）/ 业务查询（算价 + 档期，走工具调用）/ 闲聊寒暄（直接 LLM）/ 超纲问题（拒答）。
- 实现阶段：步骤 7
- 验收标准：路由测试集准确率 ≥ 90%
- 当前进度：已接入报价、知识问答、基础寒暄、档期查询及预订草案；完整安全路由与路由准确率评测仍待完成。

### F5 拒答与兜底
超纲问题（"能寄养蜥蜴吗""我家狗咳嗽吃什么药"）明确拒答并给出建议（转人工/问兽医），不编造。
- 实现阶段：步骤 7（prompt 约束 + 路由）
- 验收标准：超纲测试集中不出现编造回答

### F6 流式输出
回答逐字输出（SSE），首字延迟 < 2 秒。
- 实现阶段：步骤 8

### F7 网页界面
浏览器聊天页：对话流、引用来源展示、多轮会话。
- 实现阶段：步骤 8
- 验收标准：面试可现场演示

## 二、明确不做（边界）

| 不做 | 原因 |
|---|---|
| 真实门店下单/支付预约 | 当前仅支持本地模拟订单；不接入真实交易 |
| 医疗诊断 | 拒答转兽医，属红线 |
| B 端店家助手 | 单端策略，留作面试"未来迭代"话术 |
| 微信小程序真实接入 | 资质问题，架构预留渠道层即可 |
| 语音/多模态输入 | 与主线无关，摊薄深度 |
| 微调模型 | RAG 场景不需要，时间黑洞 |

## 三、开发顺序对照

步骤 1（rebuild 验证）→ 2（切分实验）→ 3（评测集）→ 4（混合检索）→ 5（重排序）
→ 6（多轮 F3）→ 7（路由 F4 + 算价 F2 + 拒答 F5）→ 8（F6 + F7 网页交付）

步骤 2-5 服务 F1（主链路质量），是简历数字的主要来源；F2-F5 是架构亮点；F6-F7 是交付形态。
