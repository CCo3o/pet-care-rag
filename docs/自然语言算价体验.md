# 自然语言算价：运行、观察、理解

## 这次为什么做

之前 `python -m app.pricing ...` 是开发者直接传参数给计算器。客户只会说自然语言，所以补上“理解需求、追问信息、调用函数”这一段。

客户一句话 → DeepSeek 选择工具并提取参数 → Python 校验 → 算价/检索 → 展示结果。

这是本项目的工具调用（Tool Calling）实践。模型返回工具名称和 JSON 参数，由我们的程序真正执行函数。报价的数字直接由程序排版展示，不再交给模型重新计算。

## 启动

在已经激活 `.venv` 的 VS Code 终端运行：

```powershell
python -m app.main --debug
```

等到“你的问题”出现后，直接输入中文。这里只需要一次启动命令；随后每行输入都是客户说的话。
调试模式显示工具请求及执行结果，不显示模型内部推理。普通体验去掉 `--debug`。
与独立算价器不同，这里会调用 DeepSeek API：算价或追问通常一次；知识问答需要选工具和生成回答两次。

### 对比客户视角与开发者视角

如果上面的一长段 JSON 影响阅读，先在“你的问题”处输入 `exit`，退出后再运行：

```powershell
python -m app.main
```

再次问“寄养入住需要带哪些材料？”。普通模式不打印 `tool`、`arguments`、`status` 等内部记录；正文里的 `**加粗**`、`***强调***` 会显示为普通文字，来源显示为《入住要求与疫苗规定》等文档名称。

这次改动的目的：让客户专注答案，同时让开发者仍能用 `--debug` 排查执行过程。代码位于 `app/display.py`，只处理终端显示；模型原文、工具参数、计算金额和会话历史都保留。未来网页可在展示层渲染 Markdown。当前仍是 CLI 原型，尚未实现网页客户端。

注意：改完代码要退出并重启程序；已在终端打印的旧内容不会消失，之前的会话也不会自动恢复。

## 体验一：一句话报价

输入：`一只中型犬，全程春节档期内寄养七天多少钱？`

观察：

- 工具名是 `calculate_price`。
- 参数中 `pet_type=dog`、`dog_size=medium`、`days=7`、`holiday=春节`。
- 执行结果为 `status=quoted`、`total=966.42`。
- 顾客看到中文计算过程：118 × 7 × 1.3 × 0.9 = 966.42 元。

目的：确认从“七天”到整数7的理解，以及准确计算，分别发生在不同环节。

## 体验二：信息不足，逐步补充

先输入 `/clear` 开始独立会话，避免上个例子的春节条件被继承。然后一轮一轮输入，等助手回复后再输入下一句：

1. `我家狗寄养七天多少钱？` → 应追问体型、普通还是节假日，状态 `needs_information`，此时还没有执行底层算价函数。
2. `中型犬` → 应继续问时段，并保留之前的7天。
3. `普通时段，不是春节国庆` → 应报价743.40元。
4. `那改成十天呢？` → 应保留中型犬和普通时段，报价1062.00元。

目的：理解追问需要携带历史。当前只保留本次进程最近8轮对话，`/clear`、退出或重启都会丢失；没有实现跨会话记忆。

## 体验三：回到知识库问答

接着输入：`寄养入住需要带哪些材料？`

观察工具名变成 `search_knowledge`，回答附“检索参考来源”。这是同一入口根据需求选择两条处理路径。

目的：区分查资料与执行计算。引用列表表示检索候选来源，尚未做到逐句引用验证。

## 体验四：不能算时停下来

输入 `/clear`，再输入：`一只中型犬国庆前后住十天，其中三天国庆，合计多少钱？`

应说明当前不支持普通时段/节假日分段算价，不应把10天全部上浮30%。两只合住、含洗澡接送的完整总价也暂不支持。猫房型不明会追问；五一按现有政策走普通价格。

目的：准确报价需要完整参数和明确的适用范围。模型仍可能误判或提取错误，因此必须用测试不断检查，而不是宣称“接了工具就绝对不会错”。

## 代码对应关系

- `app/main.py`：读取客户输入、显示回复和 `--debug` 信息；`/clear` 清空会话。
- `app/chat.py` 的 `ROUTER_PROMPT` / `CHAT_TOOLS`：告诉模型何时选哪种工具、参数是什么。
- `PriceRequest` / `run_price_request`：校验参数、检查范围、生成缺参追问、调用算价器。
- `ChatAssistant.reply`：把历史交给模型，按工具白名单分派，并保存完整的工具请求/结果。
- `app/pricing.py` 的 `calculate_price`：读取价格规则，用 Decimal 计算金额。

## 验证方法

```powershell
python -m unittest discover -s tests -v
python -m evaluation.chat_smoke --live
```

第一条用模拟模型输出测试程序控制逻辑，不产生 API 费用，也不能证明真实模型理解正确。
第二条运行8轮真实语言联调，会调用配置的模型 API；任一预期不符会报错，不会把失败隐藏成通过。

面试时先自己解释：“客户说一句话之后，哪些事情由模型做，哪些事情由 Python 做？缺一个参数会怎样？如何证明调用了工具？”能结合调试输出和这几处代码讲清楚，比只背术语更有用。
