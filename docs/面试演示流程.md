# 宠物寄养智慧客服：面试演示流程

建议演示时长：5 分钟。主线是“小红书顾客消息 → 浏览器插件 → Render 后端 → RAG/业务工具 → 回复”，网页聊天页和评测报告用于补充说明。

## 演示前准备

1. 用 Edge 或 Chrome 登录小红书网页版，进入消息页面。
2. 在 `edge://extensions` 或 `chrome://extensions` 中确认插件已启用，并点击一次“重新加载”。
3. 打开插件，勾选“自动监听新消息”和“普通问题自动发送”。
4. 准备三个测试问题：

   - 普通知识：`猫可以吃巧克力吗？`
   - 业务咨询：`猫咪寄养需要准备什么材料？`
   - 重要操作：`帮我预订11月1日至4日的猫标准间`

## 5 分钟演示脚本

### 1. 先讲清楚项目价值（30 秒）

可以这样介绍：

> 这是一个面向宠物寄养商家的智慧客服。商家主要在小红书接单，所以我把客服做成浏览器插件，让它直接工作在商家的聊天页面中。普通问题自动回复，预订、付款和健康问题交给商家确认。

### 2. 展示普通问题自动回复（1 分钟）

让顾客发送：`猫可以吃巧克力吗？`

展示插件自动完成：

- 监听到新消息
- 调用 Render 上的 `/api/chat`
- 从知识库检索相关资料
- 生成回复并自动填入、发送

补充说明：回答会带有知识来源，便于商家核对；插件不要求商家复制粘贴问题。

### 3. 展示业务问题和风险分流（1 分钟）

让顾客发送：`帮我预订11月1日至4日的猫标准间`。

此时展示插件标记为重要操作，并把回复填入小红书输入框，由商家确认后发送。说明原因：预订会改变库存，不能让模型在没有确认的情况下直接提交。

如果面试官追问“为什么普通问题可以自动发”，回答：系统按风险分类处理，知识问答属于低风险；预订、取消、付款、用药和健康异常属于高风险。

### 4. 展示工程化指标（1 分钟）

打开：

`https://pet-care-rag-demo.onrender.com/metrics`

解释字段：

- `requests`：后端收到的请求数
- `successes`：成功处理数
- `errors`：错误数
- `rate_limited`：触发限流的请求数
- `latency_ms_avg`：平均响应时间

再打开：

`https://pet-care-rag-demo.onrender.com/health`

说明这是服务存活检查，部署平台可以用它判断服务是否在线。

### 5. 展示检索评测（1 分钟）

打开仓库中的 `docs/检索评测报告.md`，说明测试集覆盖价格、退改、入住要求、喂养、应急处理等类别。

当前基线结果：

- 39 道测试题
- Recall@5：100%
- MRR@5：0.821

解释两个指标：Recall@5 表示正确资料是否进入前 5 个检索结果；MRR 表示正确资料平均排在多靠前的位置。强调这份报告评估的是检索阶段，最终答案还需要通过业务规则和人工抽样继续评估。

## 面试官追问时的回答

### 为什么不用纯大模型直接回答？

寄养规则、价格和入住要求会变化，纯模型容易产生幻觉。RAG 负责提供资料依据，算价和档期使用确定性代码，降低业务错误。

### 为什么做成浏览器插件？

商家的真实工作入口是小红书聊天窗口。插件把客服能力放在原工作流里，减少复制粘贴和页面切换。

### 当前版本的限制是什么？

当前插件通过网页 DOM 适配小红书网页版，属于演示和原型方案；正式产品可以接入平台官方消息接口，并增加商家账号、Redis 分布式限流、多租户知识库和持久化审计。

### 如果模型服务不可用怎么办？

后端会返回明确的错误状态，插件不会发送空消息；普通问题可以由商家接管，高风险操作默认不会自动发送。

## 演示备用方案

如果小红书页面当天无法登录，可以打开：

`https://pet-care-rag-demo.onrender.com`

用网页界面展示同一套 RAG、算价、档期和预订逻辑，再打开 `/metrics` 和评测报告完成工程化部分。面试前建议录制一段插件自动回复视频，避免网络或平台页面变化影响现场演示。
